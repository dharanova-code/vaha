# Backend review and test scripts

These scripts run the device server's own code unchanged (never modified), or transcribe/exercise firmware logic without any hardware, to produce evidence cited in three Dharanova whitepapers: *Device-to-app sync for VAHA: architecture, and the integrity and security of the current build*; *Environmental sensor bridge for VAHA: pinout, acquisition, and a TVOC data-integrity gap in the current build*; and *On-device speech-to-text: model configuration and performance on the VAHA edge device*.

Install the exact tested package versions first:

```sh
pip install -r analysis/requirements.txt
```

- `server_access_test.py` — starts the device server bound to `127.0.0.1`, seeds synthetic captures, and records HTTP status and MD5 outcomes for list/download/delete requests with no token, a wrong token, and the default token, both with the auth check on and with `VAHA_AUTH_ENABLED=false`. Also probes whether the server port speaks TLS.
- `sync_performance_test.py` — times repeated downloads against the same unchanged server to measure sync-initiation latency and transfer throughput. Runs on loopback on whatever machine it's run on — not the Arduino UNO Q, not a real Wi-Fi link.
- `dated_120_capture_session.py` — runs a full, dated session of 120 synthetic captures through the device server's side of the sync path only (list, download, delete against the server's own HTTP API). It does not exercise the companion app — there is no mobile client involved, and no claim is made about the app's own behaviour. The result is a timestamped count of the same shape as the app's "120 notes, all synced" display, produced entirely server-side.
- `inspect_release_apk.py` — reads a built APK's manifest and searches its JavaScript bundle for marker strings, to check what code a *released* build actually contains, independent of the source tree.
- `summarise_sync_runs.py` — reads `sync_performance_test_2026-10-22.csv` and `dated_120_capture_session_2026-10-22.csv` (does not change them) and writes `data/processed/sync_performance_summary.csv`: n, mean, standard deviation, min, median, max for time-to-first-byte and throughput, plus the 120-capture session's pass counts.
- `tvoc_placeholder_propagation_test.py` — calls the device server's own `CaptureService.save_capture()` with a normal TVOC reading and each of `sketch/sketch.ino`'s `readTVOC()` failure-placeholder values (`7777`, `8888+err`), then reads each back through the real `GET /api/v1/captures` endpoint, to check whether anything in the server's own code flags a placeholder as different from a real reading. Backs evidence cited in Dharanova's whitepaper *Environmental sensor bridge for VAHA: pinout, acquisition, and a TVOC data-integrity gap in the current build*.
- `readtvoc_logic_simulation.c` — transcribes `readTVOC()`'s branch logic (`sketch/sketch.ino`) into a standalone C program, with its three `Wire` calls replaced by mock functions this harness controls, to check the three return values against the source without any Arduino hardware or toolchain. Not a build of the `.ino` file. Compile with any C compiler (e.g. `gcc -o readtvoc_logic_simulation readtvoc_logic_simulation.c && ./readtvoc_logic_simulation`); tested with `tcc`.
- `gen_tts_references.py` — generates `tts_references/`: 12 known-transcript sentences synthesized with offline Windows text-to-speech (two SAPI voices) plus `tts_manifest.json` (reference text, voice, filename per sample). Already generated and committed; re-run only to regenerate.
- `wer_latency_test.py` — transcribes each file in `tts_references/` with both candidate Whisper models (`base.en`, `small`), using the exact decode options and post-processing `python/main.py` uses, and measures word error rate and inference latency for each. Runs on whatever machine it's called from, not the Arduino UNO Q.
- `summarise_wer.py` — reads `wer_latency_test_2026-10-22.csv` (does not change it) and writes `data/processed/wer_latency_summary.csv`: one row per model, with pooled word error rate (with its 95% Wilson interval), sentences with edits, transcription-time statistics, real-time factor and model load time.

Each test script writes to `data/raw/<script>_<date>.csv` and refuses to overwrite an existing file. All server-side scripts run the server locally and never touch a real device or the physical AGS02MA sensor; `inspect_release_apk.py` only reads an APK file, it doesn't install or run one; `summarise_sync_runs.py` and `summarise_wer.py` only read existing raw data and write to `data/processed/`; `readtvoc_logic_simulation.c` touches no device code at all, it's a standalone logic check; `wer_latency_test.py` runs real inference on synthetic audio, not on the UNO Q and not on real human speech.

See `data/README.md` for what each raw and processed CSV's columns mean.
