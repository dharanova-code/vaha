# Senior UX Review - Phase B

This document houses the Senior UX Evaluation and usability audit of the low-fidelity designs for Vaha.

---

## 1. Companion Application Screens

### 1.1 Home Dashboard UX Audit

#### 1. Cognitive Load
*   **Evaluation**: The default timeline card shows multiple metadata indicators simultaneously (AI title, timestamp, duration, tag chips, and multiple sensor telemetry indicators). While functional, this represents high visual noise for a simple chronological overview.
*   **Issue**: Having multiple climate, VOC, and water flow indicators visible on *every* timeline card creates visual friction during quick scanning.
*   **Proposed Improvement**: Show sensor chips only if a telemetry anomaly is detected, or collapse them under a single "Sensor Telemetry Available" ambient indicator badge unless the user hovers/taps to expand.

#### 2. Learnability
*   **Evaluation**: The "Device Status Widget" relies purely on icons or shorthand codes (`On/92%/Synced`) to communicate state. First-time users may not understand what "Synced" vs "Syncing" vs "BLE Advertising" represents.
*   **Issue**: Low learnability of hardware states in a condensed widget header format.
*   **Proposed Improvement**: Ensure a single tap on the status widget opens a micro-popover displaying clear, written label translations (e.g., "Device connected via Bluetooth; 92% Battery; All notes backed up") rather than instantly routing the user away to the Device Management Portal.

#### 3. Discoverability
*   **Evaluation**: Advanced filter configuration is hidden behind the `[+] Add Filter` chip. Users may not realize they can search by environmental attributes (e.g., "Find notes recorded when water was hot").
*   **Issue**: Low discoverability of telemetry-based search filters.
*   **Proposed Improvement**: Add placeholder search hints inside the Omni-Search Bar that cyclically change to suggest capabilities (e.g., *Try searching: "ideas in the shower" or "humidity > 80%"*).

#### 4. Accessibility
*   **Evaluation**: Small touch targets for inline Card Actions (`[Favorite]`, `[Archive]`) placed in close proximity to the card's main body tap area.
*   **Issue**: Accidental triggers where a user tries to tap the card to open it but triggers Favorite/Archive, or vice-versa.
*   **Proposed Improvement**: Expand the padding around Favorite/Archive touch targets to at least 48x48 dp, and place them along the bottom-right margin with explicit separation from the main text block.

#### 5. Navigation Depth
*   **Evaluation**: Moving to the Device Management Portal requires routing to a different screen. If a user just wants to check why sync is paused, navigating away breaks their reading context.
*   **Issue**: Unnecessary navigation depth for simple hardware checks.
*   **Proposed Improvement**: Use a bottom-drawer status panel when tapping the Device Widget, allowing quick actions (like "Sync Now") to occur inline without leaving the Home Dashboard.

#### 6. Information Density
*   **Evaluation**: Card layout is dense. The combination of Title, Timestamp, Duration, Tags, and Sensors occupies substantial vertical space, reducing the number of visible cards in the viewport.
*   **Issue**: Poor timeline scannability.
*   **Proposed Improvement**: Optimize vertical spacing by placing tags and ambient icons on the same row, separated by an elegant vertical divider, reducing note card height by ~20%.

#### 7. Progressive Disclosure
*   **Evaluation**: Telemetry is partially disclosed, but flow and temperature values are shown on the timeline cards.
*   **Issue**: Showing raw values (e.g., "Temp: 38C") in the overview card pre-empts the purpose of the Note Detail Screen.
*   **Proposed Improvement**: Replace specific numeric values on the Home Dashboard with simple ambient state icons (e.g., a "Hot Water" icon instead of "38C"). Reveal exact telemetry curves and numbers exclusively on the Note Detail Screen.

#### 8. Offline UX
*   **Evaluation**: When offline, the database query executes against the local cache, which works well. However, the Device Widget status could be misleading.
*   **Issue**: User may not understand why a recording they just made is not showing up if Bluetooth/Wi-Fi sync fails.
*   **Proposed Improvement**: Add a prominent "Pending Sync" progress indicator in the timeline if the local cache has metadata for a capture but the audio file has not transferred.

#### 9. Privacy UX
*   **Evaluation**: Audio note titles generated by AI are displayed in plaintext on the dashboard.
*   **Issue**: If a user opens the app in public, sensitive titles are immediately visible on the timeline.
*   **Proposed Improvement**: Add a "Privacy Mode" toggle option in the settings/header that masks sensitive titles (replacing them with "Private Capture - [Time]") until authenticated or tapped.

#### 10. Trust Signals
*   **Evaluation**: The app does not display encryption status on the timeline cards.
*   **Issue**: Users have no visual feedback reminding them that their audio transcripts are stored with local encryption (AES-256).
*   **Proposed Improvement**: Add a subtle, unobtrusive lock icon next to the sync status or card timestamp to denote "Encrypted Local Storage".
